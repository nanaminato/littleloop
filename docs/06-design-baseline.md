# LittleLoop 初版架构与阶段路线

版本：0.1。状态：设计基线，待实现和实验验证。范围：决策内核、角色训练、大模型协作和外部接口。后续版本可以调整模块边界、阶段顺序，或整体替换本设计。

LittleLoop 研究如何构建一个会在有限信息下做决定、从结果中学习，并逐步形成可辨识行为风格的角色。角色需要能做决定，也允许出错。任务表现、行为风格和自主程度分别评估。

## 架构与职责

| 部分 | 职责 | 初期形态 |
| --- | --- | --- |
| 决策内核 | 接收观察、目标与约束，读取角色快照，形成候选行动，选择执行、询问、暂缓或拒绝，并记录依据 | C#/.NET 类库，显式策略和可重放事件 |
| 角色状态 | 保存偏好、能力、知识索引、经历与经验策略，提供带版本的快照 | 本地存储，按需检索 |
| 训练系统 | 安排任务、收集反馈、提出角色更新，在独立任务上评测后保存新版本 | 独立 CLI 或实验宿主 |
| 大模型适配器 | 提供知识、候选行动或评估意见，返回来源与不确定性 | 可替换服务，支持超时、预算和缺失响应 |
| 输入与执行适配器 | 将文本、文件或视频等输入转换为观察，将受许可的行动交给模拟器或外部执行器 | 结构化文本输入和模拟执行器 |

先采用单仓库、多模块。训练系统通过任务和反馈接口驱动内核。内核依赖知识和执行接口，适配器由宿主装配。等独立部署、不同发布节奏或资源隔离成为实际需求，再决定是否拆仓库。

## 一次决策的契约

```text
输入事件 → 观察 → 目标与约束 → 候选行动 → 决策记录
                                        ↓
反馈与结果 ← 执行回执 ← 权限与预算检查 ← 选定行动
    ↓
训练提案 → 独立评测 → 角色快照更新
```

- **观察**记录内容、来源、时间和可信度，允许缺失或相互矛盾。视频帧等大数据通过引用定位。
- **决策输入**包含观察、目标、硬约束和角色快照版本。偏好、阅历、具体经历、提炼出的经验和知识都是按需读取的影响因素。同一次决策可以只用其中一项。
- **决策输出**记录备选方案、实际采用的因素及其证据、选择、估计风险和不确定性。记录决策时可得的依据，事后结果单独追加。
- **执行回执**记录动作 ID、结果或失败，以及是否发生外部副作用。重放时使用已记录的外部响应和回执。
- **训练更新**记录旧快照、候选变化、训练来源、评测数据和采用依据。单次失败可以产生训练提案，采用由独立评测决定。

性格主要影响取舍，例如倾向求证还是探索。经历保存具体事件，经验保存从事件归纳出的策略及其适用范围。角色可以因偏好或不完整知识选错，执行层仍按权限与预算决定是否放行。

## 大模型协作

初期和相当长一段时间内，大模型可以是主要知识供应者，也可以对具体决策给出建议。适配器记录请求用途、模型版本、返回内容、引用来源和必要的上下文标识。模型给出的推测保留其来源与状态，经过复核或实践反馈后再写入相应知识或经验记录。

具备可对照测量的任务后，可逐项比较外部建议、本地策略和混合策略的成功率、成本与失败模式。是否将某项能力迁到本地由评测决定。模型服务不可用时，内核按任务约束选择使用已有信息、询问或暂缓。

## 五个阶段

| 阶段 | 交付 | 进入下一阶段的证据 |
| --- | --- | --- |
| 1. 最小决策闭环 | 结构化事件、显式决策策略、模拟动作、决策日志与重放 | 同一记录可重放，且能复现一次合理选择、一次错误选择和一次信息不足时的暂缓 |
| 2. 大模型与角色 | 知识及决策建议适配器、可配置角色因素、来源追踪 | 同一任务由不同角色产生可解释的差异，能区分模型建议、角色经验和硬约束 |
| 3. 训练与评测 | 课程、任务生成、反馈、版本化角色更新、留出任务 | 在未见过的任务上重复测得改进，同时衡量角色风格是否稳定 |
| 4. 多模态和动作接口 | 流式观察、模拟环境、按能力开放的外部执行器 | 能处理变化与迟到事件，接收回执后修正决策，按权限约束动作 |
| 5. 指导自身构建 | 从失败记录提出知识、策略、课程或模块变更，提供评测和回退方案 | 能提交可审查的改进提案，并用独立结果说明改进和退化 |

训练中的成长按任务能力定义，例如依次处理规则明确、信息缺失和存在冲突的任务。成熟工作者的验收依据是可靠完成指定范围的工作、识别边界并适时求助。谨慎和探索等风格在相同能力水平上分别比较。

## 首阶段交付范围

选择一个可重复的模拟任务，例如为带截止时间的工单选择处理、追问信息或暂缓。固定一组情境，覆盖目标冲突、缺失信息和错误判断。记录可用行动、真实结果以及简单规则基线。

第一份可执行版本包含一个内核类库、一个 CLI 实验宿主和一组可重放样例。按以下条件验收：

1. 读取结构化事件，输出一条带角色版本和候选依据的决策记录。
2. 对执行、询问、暂缓分别生成明确结果，并把回执关联到原决策。
3. 使用同一输入、策略版本和记录的外部响应重放，选择与回执顺序可复现。
4. 能复盘一次错误决策，定位它依赖的观察或策略，并给出可检查的失败原因。

初版保留以下待定项：角色因素的组合算法、记忆衰减、模型调用协议、训练评分权重、多模态流的时序和持久化后端。用最小闭环的失败例约束这些选择。出现重构时，先保留样例、输入输出记录和复现实验，再决定哪些契约与实现需要替换。
