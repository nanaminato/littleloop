# Android 图片与文件

在聊天输入框选择「附件」，从系统文件选择器选取图片或文件，再发送。支持只发附件，也可同时填写正文和引用。每条消息可带一个非空文件，上限 5 MiB。待发气泡显示文件名和上传百分比。临时网络错误会自动重试，服务拒绝后可手动重试或移除。选择和下载通过 Android Storage Access Framework，仅访问用户选中的文件或保存位置。[Android 文件选择与保存](https://developer.android.com/training/data-storage/shared/documents-files)

点击已发送的附件打开预览。PNG、JPEG、WebP、GIF 显示静态图片，普通文本扩展名提供有限长度的纯文本预览，其他类型显示名称、格式和大小，可通过系统选择器保存。预览和下载均通过现有聊天接口，在每次访问时检查会话成员资格与消息删除状态。

入队时，文件字节分块与消息一起在一个 SQLite 事务中提交。旧版 SQLite 队列升级保留已有数据。上传及发消息共用持久客户端 UUID。服务端将重复上传限定在相同所有者、文件名和内容，消息仍按会话、发送者、客户端 UUID 去重。链路断开时保留整份附件，重试可重新上传完整文件。

## 实测

使用 Android 17 模拟器、Chrome 和真实 MySQL。网页通过文件输入框发送图片、文本文件，Android 可看到图片和文本预览，用系统选择器保存后 SHA-256 匹配。Android 从系统选择器发图，并在断网时将文件入队。移走测试原件、强制停止再重开应用后，文件仍待发送，网页在恢复连接前查不到该文件。恢复后网页收到图片和文件，下载内容与原始文件一致。

两位会话成员可获取附件，第三个非成员账号访问返回 404。在会话内借用其他用户的附件 ID 发信被拒绝，其他用户也无法复用已分配的上传 ID。原发送者重交相同上传得到相同附件 ID，修改内容后重交得到 409。使用相同客户端 ID 重发消息得到原消息序号，历史仍只有一条。Android Debug 构建、Lint 和 .NET 构建通过。本机证据位于 `data/chat-android-attachments/`。
