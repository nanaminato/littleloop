# 聊天平台升级设计

状态：设计稿。当前[开发工作台](22-workbench.md)已通过 Chrome、MySQL 和 RelaxKonOS 执行验证，现有入口为本机单用户、单对话、单项目。

## 产品与交互

产品定位为供个人和小团队私有部署的即时通讯工具。登录后进入会话列表，可以独立发起私聊、私有群和个人收藏，收发文字、图片、文件，回复、转发、搜索、置顶与静音。借鉴 Telegram 的会话组织和消息操作，保留自己的服务端和数据。普通聊天在没有机器人时仍完整可用。[Telegram FAQ](https://telegram.org/faq)

- 桌面左侧为会话列表，有搜索、头像、消息摘要、未读、置顶和归档。中间为消息和输入框，详情按需打开。手机先用响应式 Web，列表、会话和详情逐页切换。
- 人和机器人消息用同一时间线。每个任务有一张稳定卡片，状态更新留在原卡片。待审批通知可跳回原消息，审批详情仅对授权者可见。
- LittleLoop 可以单聊，也可以安装到群。普通群聊保持正常交流，明确提及机器人或通过消息菜单分享上下文才触发机器人。安排开发任务要单独确认目标、项目、验收和授权范围。

RelaxKonOS 示例：两位开发者在项目群讨论一段代码，回复原消息并明确 @LittleLoop，选取源码行。机器人带着文件、版本和行号回答。用户从回答安排任务，后台执行期间仍能聊天。授权人打开审批卡，团队在原处查看允许共享的结果，授权者进一步看补丁和测试输出。

## 技术和数据

沿用 Angular、ASP.NET Core、MySQL。先做模块化单体，内部划分身份、通讯、附件、通知和机器人集成。REST 承担发送、查询历史和审批，SignalR 推送更新。附件初期存本地目录，通过接口鉴权下载，留出对象存储适配边界。Android 有明确的原生通知或分享需求后，用 Kotlin 与 Jetpack Compose 复用接口。

| 数据 | 首期设计 |
| --- | --- |
| 账户与设备会话 | 邀请制注册、登录、退出和撤销设备。浏览器用安全 Cookie，变更请求校验防跨站请求令牌 |
| 会话与成员 | 私聊、私有群、个人收藏。存成员角色、加入边界、已读游标、通知偏好 |
| 消息与同步事件 | 会话内序号、客户端消息 ID、发送人、回复关系、内容类型。编辑和删除产生同步事件 |
| 附件 | 元数据进 MySQL，文件存储独立。下载重新检查会话成员权限 |
| 集成与任务 | 存安装范围、明确授权的引用快照、运行状态、审批和产物可见范围 |

发送时在同一事务写入消息和待推送事件。提交后再通知在线客户端，重复消息 ID 返回已有记录。重连用游标补拉，服务端序号确定会话顺序，已读跨设备同步。历史按页读取。成员授权统一应用到历史、搜索、附件和订阅，撤销后停止推送与读取。群管理员身份本身不等同于项目执行授权。

## 机器人边界

聊天层只识别机器人身份、触发消息和结构化卡片。适配器通过版本化接口接收消息和明确共享的上下文，返回回复、引用与任务事件；权限按安装范围绑定。逐步支持第二种机器人来检验接口。客户端用固定组件渲染消息、引用、任务、审批和产物卡片。

LittleLoop 适配器复用项目权限、核心判断和经验。任务执行器运行在有项目授权的工作机，接收已注册的项目和固定命令，不从群消息取得执行权限。审批绑定同一任务的具体请求、授权人和到期时间，只能消费一次。发送任务与批准执行分别授权。机器人移除后停止新调度和读取，已有运行按原授权和可用取消操作处理。刷新、重试和重启不产生重复副作用。运行中断且执行结果未知时进待核对。

## 实施顺序

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| A · 通讯基础 | 独立账户、私聊、私有群、文本、回复、历史、未读、重连 | 两个真实浏览器会话互发，第三个非成员无法读取或订阅。断线、重发、刷新和重启后检查顺序及重复 |
| B · 日用体验 | 图片和文件、搜索、编辑、删除、转发、置顶、归档、收藏、通知 | 跨设备已读，附件访问权限，编辑删除同步，手机界面可用 |
| C · LittleLoop 适配 | 机器人身份、源码引用、任务卡、授权与结果、旧工作台导入 | 两个账户在 RelaxKonOS 隔离工作区重跑全流程，验证无关成员和重复审批被拦截，重启恢复记录 |
| D · 扩展 | 第二种机器人、群话题、频道，评估原生 Android 与音视频 | 第二个适配器通过同一接口，频道和通知按新角色模型验收 |

A 完成后 B 和 C 可分别推进。当前对话采用 MySQL 单行 JSON。升级使用新表和显式导入，将旧消息搬入「历史工作台」会话，保留消息 ID、回复、任务标识及回执位置。旧记录没有多人身份，导入绑定到明确指定的所有者。历史任务保持历史状态，未知运行转待核对。导入幂等，核对消息和任务计数、回执链接，再切换入口。旧入口可用于回退。

设计假设为邀请制私有部署、Web 优先、云端多设备同步。公开注册、公开频道、端到端加密和通话单独定义范围。实现先从阶段 A 的双人实时聊天开始。
