# S2 · 多任务协作者

2026-11-18 用户确认开始 S2 的设计与实现，正式验收可延后。

## 本次设计

聊天目标继续由 `chat_bot_work` 持久化，单个聊天 worker 持有数据库租约，串行处理消息、通知和任务派发。执行可以并发。默认最多两个任务和一个源码问答同时在途，部署可以分别配置上限。主项目、协作机器人和相同或嵌套工作区共用互斥资源。等待审批时保留工作区占用，避免两个任务基于不同的源码快照修改同一项目。已有任务的审批、权限、预算和结果版本检查继续由原执行宿主负责。

在有空位时按创建顺序找出最早可运行的任务。工作区已被占用的任务留在队列，其他工作区可以继续。任务补充、暂停或取消后，仍等旧执行真正退出才释放进程内占用。重启统一按已有状态和执行证据恢复，排队任务可继续，未知执行进入待核对，安全的审批边界和协作审阅检查点沿用原规则。

后续增量在持久目标层增加显式优先级、依赖及承诺视图。依赖应基于明确的同范围目标引用和受控完成证据，优先级需要随等待时间老化。共享角色经历和角色总预算应复用核心运行时的契约，仍需解决聊天 SQL 与执行状态文件的事务边界。

## 配置与使用

`ChatBot__MaxConcurrentTasks` 默认 2，`ChatBot__MaxConcurrentQuestions` 默认 1，均允许 1–16。默认开发机器人和协作机器人使用主项目。已配置独立项目的开发机器人使用各自的工作区。源码问答使用独立容量，带工作目录的 ACP 问答也参与目录冲突检查。

同一会话里有多个未结束目标时，发送“进度”会显示自己的目标数量和最早八项的状态。回复目标任务卡可查看单项进度，也可补充、暂停、恢复或取消。
