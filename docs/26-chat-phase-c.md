# 阶段 C · LittleLoop 聊天机器人

聊天入口沿用 [阶段 A](24-chat-phase-a.md) 和 [阶段 B](25-chat-phase-b.md)。普通聊天始终可用。启用机器人后，操作员可打开 LittleLoop 私聊，或在自己所属的群中安装或停用机器人。普通消息中的机器人名字只是文本。源码提问和开发任务分别通过页面动作明确提交。

## 配置

在聊天服务启动环境设置：

| 设置 | 用途 |
| --- | --- |
| ChatBot__Policy | 指向 [有限开发策略](21-codex-development.md)，配置 Codex 可执行文件、工作区、允许修改的文件、命令和受保护的测试入口 |
| ChatBot__Data | 独立运行目录，位于项目根目录之外。保存问答会话日志、任务审议、工具回执和一次性审批记录 |
| ChatBot__Operators | 逗号分隔的聊天账号名，可以安装机器人、选择源码和创建任务 |
| ChatBot__Approvers | 逗号分隔的聊天账号名，可以处理自己所属会话的任务审批 |

用户名 littleloop 为系统保留。机器人账号无法作为人与网页登录。当前一个部署绑定一个受限项目策略，建议使用隔离项目副本。任务队列串行执行，后台独占数据库工作租约和本地执行目录。

## 操作与可见范围

1. 在 LittleLoop 私聊或已启用机器人的群中点击「引用源码提问」。选文件和行范围，输入问题。LittleLoop 在同一时间线上回复，卡片保留文件、行范围、摘录和 SHA-256。群成员可见明确分享到该群的摘录。
2. 在任意可见来源消息下点「安排开发任务」。数据库在同一事务保存卡片消息和待执行任务。队列项冻结目标、引用及来源文本。开跑前检查引用哈希，变化后需重新引用。
3. 只有同时满足会话成员资格及审批账号配置的人可以看审批参数并提交决定。开发桥接还会检查项目策略和核心判断。审批绑定当前任务与 nonce，第一次通过原子写入决定，记录审批账号 ID。重复提交返回 409，发起任务的权限本身不能批准工具动作。
4. 任务卡显示状态。发起人和审批人可看补丁及实际测试回执。审批请求参数仅向审批人返回。聊天服务重启后，已完成记录可以重新打开；执行中断的任务进入待核对，保留回执，不自动重跑。

群维护由配置的操作员完成。停用后停止新的调用，尚未开始的任务会被置为停用；已经执行的任务按既定审批继续。当前只注册 LittleLoop 适配实现。

## 导入旧工作台

配置 ConnectionStrings__LegacyWorkbench 指向旧数据库，或配置 ChatBot__LegacySnapshot 指向导出的旧 conversation.json，二选一。配置 ChatBot__LegacyOwner 绑定已存在的账号。如需打开旧补丁与测试回执，将 ChatBot__LegacyData 指向旧工作台的运行目录。

启动后该账号可看到「历史工作台」。消息使用原始 ID 作为导入键，保留回复和源码引用。任务保留原 ID 和完成状态。旧的排队或执行中任务作为待核对的历史记录，不重新执行。重启重复导入同一来源时复用原记录。历史会话只允许绑定账号查看，旧数据供导入读取。


## 实测

2026-11-15 使用两个真实 MySQL 数据库及两个独立 Chrome 登录会话。alice_c 发起工作，bob_c 审批。实际运行如下：

- 从旧工作台的 MySQL 导入 2 条消息和 1 项任务，保留回复、源码引用和真实回执；另一账号无权读取历史会话或历史任务。
- 真实 Codex 在机器人私聊和 RelaxKonOS 项目群各回答一次源码问题，普通群消息没有触发任务。
- 从群回答创建任务 4462198b-8244-41be-bc8c-7a00687f2b4e。发起人使用当前真实 nonce 请求审批，每次收到 403。审批人在浏览器放行基线测试、补丁与复测，每次重放得到 409。任务目录有 3 条批准人审计记录，实际有 1 次源码修改和 2 次测试回执。
- 基线测试复现应用 ID 末尾换行问题，隔离副本修复后 19 项通过。重启聊天服务后，在新的浏览器会话恢复群任务、补丁、两次测试回执和同一组导入 ID。MySQL 8.4.13 中有 2 项已完成问答、1 项已完成开发任务、1 项导入任务。
- Angular、聊天后端与旧工作台编译通过，LittleLoop 原有 308 项检查通过。

证据位于 Git 忽略的 data/chat-phase-c，包括 approval.png、completed.png 和 after-restart.png。
