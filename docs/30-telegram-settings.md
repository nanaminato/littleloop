# Telegram 式设置补齐

本次升级扩展 [聊天界面](29-telegram-ui-implementation.md) 的四项设置。启动时增量建立用户名保留、屏蔽、设备推送订阅和待发队列表。

- **用户名**在「编辑资料」内修改。修改后使用新用户名登录，旧名为原账号保留，不能由其他人注册。聊天、设备、任务和机器人授权都以账号 ID 关联。部署者原先配置的账号名可通过保留名解析到同一个 ID，旧工作台导入也沿用同一所有者。历史消息的发送身份会显示当前用户名，已转发的来源标签保留转发时的快照。
- **屏蔽名单**在「隐私和安全」内维护。双方被阻止继续互发私聊或创建对方参与的新私聊和新群。已有聊天记录及已有共同群的交流保留。解除屏蔽恢复私聊，名单随账号保存。
- **中英文**覆盖聊天列表、登录、搜索、菜单、设置、机器人卡片、应用提示和系统会话名称。切换跟随浏览器设备保存。用户输入、群名、机器人原文和工具回执以原始内容显示。
- **后台推送**从「通知和声音」对每个登录设备单独启用，需浏览器允许通知。关闭聊天标签页后，Service Worker 可接收通知，点击可打开对应会话。未读、静音、消息预览、屏蔽和成员权限在投递前重新检查。退出或撤销会话会删除关联订阅和待发记录。

## 运行与维护

本机回环地址可作为浏览器安全上下文，远程部署应提供 HTTPS。服务首次启动在数据保护密钥目录生成 web-push.json，并在重启后复用。可用 ChatPush__KeyFile 指定专用密钥文件，用 ChatPush__Subject 指定部署联系地址。更换 VAPID 密钥后需重新订阅。

采用标准 Web Push 与 AES128GCM，服务只向已知浏览器推送网关的 HTTPS 端点发送。订阅、队列和设备会话保存在 MySQL。网络暂时不可达时队列重试，待发最长 15 分钟。网关报告永久失效时移除订阅。应用不会在重启时重发已出队的通知；极端中断后同一会话的通知由浏览器标签合并。

参考 [Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API) 和 [Lib.Net.Http.WebPush](https://github.com/tpeczek/Lib.Net.Http.WebPush)。
