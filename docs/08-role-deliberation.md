# 结合角色、经历和目标的审议流程

后续增量：[执行反馈学习闭环](09-execution-learning.md) 已将经历接入持久化宿主；新任务可省去角色和经历数据，执行回执与反馈会自动影响下次输入快照。本文描述的 v2 推理契约保持兼容。

2026-11-14 用户进一步明确：核心决策不能只靠规则打分，需要结合角色偏好、经历和目标，主动质疑前提、提出新方案、拒绝并说明原因。已实现的 v2 是结构化符号推理和经历检索；不声称能从任意自然语言自行理解世界或产生创造性规划。

## 输入与流程

`DeliberationInput.Cognition` 是随决策保存的角色审议快照，包含以下内容：

| 内容 | 作用 |
| --- | --- |
| Goals | 目标结果、优先级、是否必须满足；高优先级先比较 |
| Preferences | 偏好或回避的行为特征及优先级 |
| Boundaries | 角色不接受的结果及理由；与执行权限分开 |
| Premises | 假设、期望真假值、是否影响整个目标 |
| Evidence | 对命题的观察、来源、置信度和稳定 ID |
| Experiences | 情境条件、曾采用的行动、成功/失败、来源和教训 |

候选的 `Meaning` 声明策略标识、预期结果、行为特征和依赖的前提。标签使用精确匹配；目标文本只用于说明，机器决策依据显式结构。预测结果是模型声明，不是执行成功的保证。插件与输入来源均保留，当前不验证提供方声明是否真实。

流程先检索与当前事实条件全部匹配的经历，把能够满足当前目标的成功策略重新提出为候选，记录 `experience:*` 来源。这样即使输入只提供“直接处理”，核心也可以根据之前处理类似争议的经历提出“请专员复核”。这是已有策略迁移，尚不是自由生成新技能或多步计划。

随后检查前提。置信度至少 0.75 的支持和反对证据同时存在时保留冲突；只有反对证据则标为被反驳；没有足够支持则标为未知。低置信度证据不会被当作证明。该阈值是未校准的首版工程选择。目标关键前提未知或冲突时，核心主动输出 Reframe；仅行动前提不足、且无其他可行行动时输出 Ask。不同方案可以依赖不同前提，不因一个方案失败就否定全部方案。

行动必须有语义模型、满足必需目标、不触及角色底线、没有未解决的前提或相同情境策略失败反例，并通过现有权限、预算、风险检查。匹配的失败经历作为反例，会阻止直接重复同策略；目前采用保守处理，没有自动判定旧失败已被修复或遗忘的机制。

必需目标与角色底线直接冲突时，输出 Refuse，并引用目标与底线解释拒绝。一个坏方案不等于坏目标；方案触及底线只会排除该方案。权限不足则暂缓，而不是虚构价值观拒绝。

对于剩余可行行动，依次比较有序目标、角色偏好、匹配的成功经历，再以更低风险、成本和稳定 ID 解决平局。`Value` 分数在 v2 不参与选择。这里只在已论证可行的行动之间作取舍，偏好或高分无法抵消前提冲突、底线或权限。

每个决定保存 `Reasoning`：目标、回忆、证据与前提关系、生成的方案、各方案反对理由、最终选择、与其他可行方案的取舍。理由直接来自参与判断的记录。插件提出的 Ask/Reframe/Refuse 在 v2 作为建议保留，不能靠分数直接强制核心拒绝；核心根据自己的结构化上下文独立推导这些结论。

## 示例与验证

```powershell
dotnet build src/LittleLoop.Cli -m:1
dotnet run --no-build --project src/LittleLoop.Cli -- deliberate examples/role-deliberation/recall.json > trace.json
dotnet run --no-build --project src/LittleLoop.Cli -- replay-deliberation trace.json
dotnet build tests/LittleLoop.Checks -m:1
dotnet run --no-build --project tests/LittleLoop.Checks
```

这些示例无需插件：`careful.json` 与 `fast.json` 对同任务体现不同角色偏好；`recall.json` 从经历提出原候选外方案；`question.json` 根据观察反驳目标前提；`refuse.json` 根据角色底线拒绝目标。它们不依赖旧示例的 `goalConflict`、`premiseConflict` 或 `alternativeRoute` 特殊开关。

检查覆盖角色差异、目标优先于偏好、经历迁移、无关经历排除、失败反例、矛盾/缺失证据、拒绝理由、权限边界、嵌套快照隔离和确定性重放。插件可读取完整角色快照并提出带 Meaning 的新行动；宿主给每个插件完整深拷贝，防止普通集合修改污染后续判断。进程内插件仍必须可信。

无 `cognition` 的既有输入继续使用 `deliberation/1`；有完整快照时使用 `deliberation/2`。重放使用原始快照和已记录插件输出，不重新请求插件或外部执行。原阶段一模拟工单流程保持独立。直接调用 `deliberate` 时由输入提供经历；新的学习宿主会自动组装经历快照。跨情境归纳、独立训练评测和性格更新仍待实现。
