# Android 好友与群成员管理重构

2026-11-15，依据用户明确要求，延续 [会话与频道管理重构](44-android-conversation-refactor.md)，拆分好友和群成员页面的组件与业务状态，统一权限判断，保持现有功能，并实际回归。领域行为仍以 [好友和群成员设计](39-chat-friends-and-group-members.md)及当前服务端为准；没有修改接口、数据模型、同步协议或群／话题联动事务。

## 边界

代码位于 `src/LittleLoop.Android/app/src/main/java/dev/littleloop/chat/social/`。

| 文件 | 职责 |
| --- | --- |
| `ChatSocial.kt` | 好友和群成员页面的装配入口 |
| `FriendsContent.kt` | 好友列表、各关系状态及操作按钮 |
| `FriendsState.kt` | 账号隔离的草稿、好友请求／响应、打开私聊 |
| `GroupMembersContent.kt` | 成员列表、身份标记、当前可用菜单 |
| `GroupMemberDialogs.kt` | 成员操作确认与加入申请审核组件 |
| `GroupMembersState.kt` | 账号／群隔离的状态、邀请与操作提交、加入申请轮询 |
| `SocialComponents.kt` | 共用用户名输入表单和错误显示 |
| `SocialPermissions.kt` | 好友状态权限、群权限和类型化成员操作策略 |

展示组件只读取数据并发送事件，不调用 Repository。控制器继续使用既有 Repository 的忙碌状态、错误处理、SignalR 刷新和成员操作接口，避免建立第二套同步机制。

好友草稿按账号保存，群成员草稿和待确认动作按账号与群 ID 保存。配置变化保留原有可保存状态；加入申请列表和审核展开状态仍为临时状态，重新进入时加载。提交成功只清除与本次提交一致的草稿，避免覆盖之后输入的内容。

## 共享权限

- 只有收到的好友申请可接受／拒绝，只有已成为好友的条目可进入私聊；控制器提交时重新解析当前关系。
- 群主可以邀请、审核加入申请、管理管理员和转让群；管理员只可移除、禁言／解除禁言普通成员。
- 群主、机器人、本人均不可作为成员管理目标；管理员不可操作其他管理员。
- 普通成员和禁言成员仅查看列表；禁言本身不替代管理身份的判断。
- 菜单、已打开的确认弹窗和提交事件共用 `memberOperations`，依据最新操作者与目标成员状态。目标升为管理员／群主、离群，或操作者失权时，原确认动作不再有效。审核加入申请也重新检查当前群主身份。

以上是客户端操作入口规则，服务端继续最终授权。状态切换期间的过期确认现在与菜单一致，不增加新的业务权限。
