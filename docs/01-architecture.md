# 认知架构与模块设计

## 认知循环

输入事件 → 感知候选 → 注意力筛选 → 工作记忆 → 关联检索 → 假设/推理 → 行动候选 → 权限检查 → 执行 → 反馈 → 学习/巩固。

允许循环暂停、重试、回溯和离线整理；不要求所有过程在同一线程执行。

## 建议模块

| 模块 | 职责 |
| --- | --- |
| Host | 生命周期、配置、预算、事件调度 |
| Perception | 视觉、听觉、触觉与输入标准化 |
| Attention | 兴趣、显著性、目标相关性、资源分配 |
| WorkingMemory | mini 临时存储、短期上下文、候选假设 |
| Memory | 情景/语义/程序记忆、关联、遗忘、巩固 |
| Knowledge | 概念、映射、规则、范式、来源与矛盾 |
| Reasoning | 演绎、类比、近似判断、假设检验 |
| Learning | 经验更新、迁移、元学习、自评估 |
| Motivation | 指令目标、身份/角色约束、探索偏好 |
| Action | 工具注册、能力发现、沙箱、执行与审计 |
| Reflection | 行动评价、失败归因、知识修正 |
| Storage | 可替换持久化、索引、后台整理 |
| Diagnostics | 事件追踪、重放、状态快照、指标 |

## 模块契约

每个模块声明：标识、版本、输入/输出 schema、能力、权限、依赖、资源预算、状态迁移、失败语义和诊断接口。模块可包含预置知识或完整功能；区分预设行为与学习获得的行为。

模块生命周期：发现 → 校验 → 加载 → 观察 → 评估 → 更新/隔离 → 废弃。模块反馈包括成功率、延迟、资源成本、错误类型、知识来源与不确定性。自生成模块仅先生成受限规则或声明式组合，必须经过测试和人工可控审批才能启用。

## 并发与线程安全

“模拟人的非线程安全思考”作为研究问题，不作为允许数据竞争的工程规范。单个认知主体的可变状态由串行事件循环/actor 持有；耗时识别、索引、联网、整理在后台运行，结果带版本号返回。使用消息、不可变快照、乐观版本检查；过期结果拒绝或重新评估。

## 开放接口

C# 接口优先；适配器可为进程内插件、受限子进程或远程服务。API 采用版本化契约；权限最小化，外部工具执行可取消、超时、记录、回放。避免将特定模型、数据库、操作系统绑定到认知核心。

## 初期数据结构草案

`CognitiveEvent`、`Percept`、`ObjectTrack`、`Concept`、`Relation`、`MemoryRecord`、`Hypothesis`、`Goal`、`ActionProposal`、`Feedback`。

每条记录至少考虑 ID、时间、来源、置信度、关联、版本与可审计的更新历史。
