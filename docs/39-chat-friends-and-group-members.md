# 好友申请和群成员管理

网页版在主菜单提供「好友」。Android 在会话列表提供同名入口。输入对方用户名即可发送申请。收件人可接受或拒绝，申请人可查看待处理状态。好友列表可打开两人已有的私聊，也可创建私聊。

新群的创建者自动成为群主。网页版从会话头像打开会话详情，Android 从群聊进入「群成员」。群主可按用户名邀请成员、移除成员，或把群主转让给现有成员。普通成员可查看成员列表。邀请遵守接收方的群邀请设置和双方的屏蔽规则。转让后，原群主仍是成员。

群聊可以只填写群名称创建，初始成员仅为群主，其他成员可稍后邀请；Web、Android 和接口规则一致。见 [本轮实测](42-chat-ui-audit.md)。

好友关系按稳定的账号 ID 保存。群成员变更在一个 MySQL 事务中同步到群聊和已有话题。移除成员保留其已发送的消息，并撤销其对群聊及话题的访问。SignalR 通知在线客户端重新读取当前关系和权限。Android 在获得最新成员权限后清除已撤权会话的历史缓存。

## 添加 LittleLoop 好友

2026-11-19，用户确认用好友申请开通机器人私聊，并要求名单实时生效和工具逐项审批。用户在「好友」输入 `littleloop` 并发送申请。名单内的账号自动通过，服务在同一事务中记录好友关系并开通或复用私聊。名单外的账号会看到待接受的申请。

网页的「好友 → LittleLoop 访问管理」供访问管理员使用。管理员可增删自动通过名单、处理待确认申请，并撤销手动授予的访问。新加入名单时，系统会自动接受这个账号已有的待处理申请。移出名单会撤销由名单自动授予的访问。手动授予的访问可以单独撤销。权限以 MySQL 中的账号 ID 为准，名单调整无需重启。部署可用 `ChatBot__AccessAdmins` 指定访问管理员，未配置时使用现有审批员名单。

撤销会停止新消息和工具请求，取消该私聊中尚未结束的任务，并保留历史消息。正在执行的任务在既有协作边界停止。外部效果仍按原规则对账。通过好友申请后，用户可以发送普通消息、使用私聊记忆、创建开发任务。需要审批的补丁和命令继续交给工具审批员逐项处理。新的权限仅适用于用户与默认 `littleloop` 的私聊。现有操作员和其他机器人继续使用原角色配置，纳入好友管理的账号在该私聊使用数据库权限。

本轮 SQLite 和隔离 MySQL 各通过 213 项聊天检查，包含旧申请、即时撤销、在途任务停止、重新授权和普通好友回归。`python tests/ChatContinuousLive/direct_http_e2e.py --friend-access --friend-tools` 在隔离服务通过 8 项真实 HTTP 检查。真实 Codex 的补丁和测试命令分别等待独立审批，访问管理员和机器人好友的审批请求均返回 403。结果保存在 `data/direct-http/0bb8a98e/result.json`。桌面 Chrome 与窄视口的网页验证还覆盖了自动打开私聊、待审状态、管理员确认和撤销后的历史保留，记录位于 `data/friend-access-browser/30643286/`。

已部署到现有 5190 Chat。切换前备份了真实 MySQL、前一版发布清单和服务启动配置。上线核对了新版 Web 资源、管理员入口和真实数据库名单。保留原体验私聊，把体验账号从启动配置迁到数据库自动通过名单，等待用户亲自发送好友申请。部署证据保存在 `data/continuous-deployment/bot-friend-access-deployment.json`。

旧群的数据没有可靠的创建者记录。此升级保留其成员和消息，旧群的群主仍待明确指定。

## 验收

在 Android 17 模拟器、真实 Chrome 和现有 MySQL 上用三个测试账号完成验收。

- Android 发起好友申请，Chrome 接受，双方从好友列表打开私聊。Android 拒绝另一条申请后，Chrome 的待处理记录实时消失。服务重启后，已接受的好友关系仍可读。
- Chrome 邀请成员、转让群主，Android 群成员列表和操作权限随即更新。普通成员尝试邀请、移除和转让均收到 HTTP 403，原群主在转让后也收到 HTTP 403。
- Android 新群主指定并移除成员，Chrome 中被移除的账号退出正在查看的话题。群聊和话题的会话列表均移除对应条目，读取历史、读取成员列表和发送消息均收到 HTTP 404。其原有消息仍可由群成员读取。
- .NET、Angular、Android 构建和 Android lint 均通过。
