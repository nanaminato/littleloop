# 对话界面审查与修复（2026-11-15）

本轮根据用户要求检查 Web 对话的会话类型、权限角色、桌面和手机布局，直接修复问题并运行浏览器验证。群聊允许不填写初始成员，创建者自动成为群主，随后从会话详情邀请成员。私聊仍要求一个有效的其他账号，群邀请和屏蔽规则保持生效。Android 同步放开创建入口并修复消息管理菜单。

## 已修复

- 频道详情的复选框不再继承全宽文本框尺寸；管理表单有独立分组、留白、按钮和长文本换行。
- 新建群聊的 Web、Android、接口和存储层均允许空成员列表；两端说明成员可选。
- 全局搜索箭头实际提交搜索。搜索结果和频道目录独立滚动，不把消息列表或输入区挤出屏幕。
- 新建会话表单按视口限高滚动。消息菜单按按钮上、下可用空间限高，避免盖住触发按钮；Esc 优先关闭当前菜单并归还焦点。
- 群话题和共享媒体先过滤再判断空状态，删除附件不作为共享媒体显示。
- 转发列表排除没有发言权限的目标。
- Web 和 Android 的群主／群管理员可从普通消息菜单删除他人消息，但不能编辑他人消息。频道在群中的同步帖子副本隐藏服务端不允许的编辑、删除入口。
- 讨论管理员不是关联群群主时，选择框仍显示当前关联群；讨论管理入口根据最新会话权限更新。
- 评论、好友长名称和附件相关布局补充宽度约束及换行。
- 长频道名的帖子同步曾因 `forwarded_from VARCHAR(32)` 返回 500；字段扩为与频道名称上限一致的 100 字符，启动时在既有 schema 锁内幂等扩容，保留原有数据。

## 实际覆盖

| 范围 | 本轮检查 |
| --- | --- |
| 私聊、个人收藏 | 时间线、详情、消息菜单、搜索、回复、编辑、转发和删除确认 |
| 群聊 | 群主、管理员、普通成员、禁言成员的时间线、成员和详情菜单 |
| 群话题 | 群主、普通成员、禁言成员；独立时间线、返回群和详情 |
| 频道 | 所有者、发布管理员、订阅者；帖子、评论、详情、管理记录、删除确认 |
| 单项频道授权 | 发布、编辑、删除、置顶、资料、订阅者、讨论七项分别授予，另检查零权限；核对消息和详情控件可见性 |
| 周边界面 | 登录、会话创建、频道／话题弹窗、主菜单、好友、目录、全局／会话搜索、全部十个设置子页 |
| 尺寸 | 主矩阵 1440×900、1024×768、390×844、320×568；补充 667×375 横屏低高度 |
| 外观 | 中文浅色、英文深色、大字号，长消息、长频道名、长附件名 |

主矩阵记录 **165 个界面状态**，周边页面记录 **96 个界面状态**。这些数字是截图／布局检查状态数，不是 261 个独立功能测试。最终脚本同时断言关键滚动容器没有横向溢出、无浏览器未捕获异常，检查发言输入框及管理入口与角色匹配。

实际操作另外验证了：网页只填群名创建成功、初始仅群主一人、随后邀请成员；普通成员邀请返回 403，空私聊和空群名返回 400，非成员读取返回 404；禁言及只读频道发送返回 403。通过 UI 实际发送、编辑、转发、群管理员删除他人消息、上传附件并逐字节下载比对、发送评论。长频道名关联讨论群后成功发布及同步。

Android 17 模拟器覆盖安装最终调试版，实际创建 `Native_Audit_Empty_Group`（成员为空），随后从成员页面邀请合成测试账号；最终版本长按他人消息出现删除、未出现编辑。`:app:assembleDebug`、`:app:lintDebug` 通过。本轮原生 Android 是上述变更的定向复验，**没有把 Web 的完整角色／尺寸矩阵算作原生 Android 验收，也没有进行实体手机复验**。

机器人卡片另有 6 个**合成响应渲染**场景：1440／390／320 宽度下的普通阅读者与审批者，展开源码引用、补丁、回执和执行报告，断言审批按钮只向审批者显示。没有提交审批、执行开发任务或重新验收推送送达；这些仍以各自功能文档中的既有证据为准。历史工作台不是新的建群类型，其卡片渲染复用机器人组件。

## 证据和重跑

本机截图与 JSON 在 Git 忽略目录 `data/chat-full-audit/`：

- `result.json`、`extras-result.json`：主矩阵与周边界面的状态、溢出和脚本错误记录。
- `actions-result.json`：单项授权及真实消息操作；`bot-visual-result.json` 明确标注合成渲染。
- `android-create-optional.png`、`android-empty-created.png`、`android-admin-menu.png`：原生创建与管理菜单。
- `main-result.json`、`live-group-invited.png`、`live-channel-rights.png`：原地址 5190 在更新后的实测结果。

浏览器脚本保存在 `tests/ChatUiAudit/`。从仓库根目录运行，需要本机已安装 Chrome、`data/workbench-browser/node_modules/playwright`，以及既有测试配置 `data/chat-phase-a/chat.local.env`（只从本地读取凭证，不输出值）。服务地址由 `CHAT_AUDIT_BASE` 指定，默认是本轮专用服务 `http://127.0.0.1:5193`。输出目录需存在。脚本会创建合成账号和测试会话，使用真实测试数据库。

按顺序执行，避免操作脚本新增消息干扰布局脚本正在打开的菜单：

```powershell
node tests/ChatUiAudit/audit.cjs
node tests/ChatUiAudit/extras.cjs
node tests/ChatUiAudit/actions.cjs
node tests/ChatUiAudit/bot-visual.cjs
```

Web `npm run build` 和服务端 `dotnet build src/LittleLoop.Chat --no-restore -m:1` 通过。原 5190 实例已复用现有数据库、密钥、机器人和推送配置重启到本轮后端构建，并在该地址再次通过空群创建、后续邀请和频道详情检查。
