# 持续自主工作验收

2026-11-20。主聊天已有统一决策入口、目标版本和原生 Harness 恢复。此次沿用这些接口，在目标账本加入定时唤醒，再用真实长任务与配对样例测量效果。第一阶段的模拟工单仍用于离线研究和重放。[现有闭环](58-autonomous-bot.md) · [阶段基线](06-design-baseline.md)

## 到期由同一个 Bot 决策

`Wait` 可为已有目标附带 `wakeAfterSeconds`。宿主按提交时的 UTC 时间计算到期时间，和等待状态、目标版本一起保存。延迟范围为 5 秒至 7 天，每个目标累计最多安排 32 次检查，与 Harness 回合预算分开。到期后，同一 `IBotDecisionEngine` 收到 `Timer` 观察，可以委派、继续等待、随等待汇报，或在证据足够时完成。普通等待仍可由用户消息推进。

调度不单独决定任务动作。提交时重新检查目标版本、定时标记、权限和用户收件箱。一次成功提交在同一事务消耗旧定时事件、保存决策并更新下一状态。暂停、取消、完成和修订清除旧时间。重启后，超时的等待从持久状态恢复。权限仍取当前会话。系统提供一次性时间检查和已有消息、回执事件，尚无用户自定义条件表达式或周期规则。

## 本地证据判断

本轮新增 `local/unsubmitted-budget/1`。目标仍处于首版决策边界，首轮派发明确未送出、回执与工具记录无冲突、剩余 Harness 回合为零时，Bot 可以直接说明本轮未送出并等待。旧日志的提交标记保持未知；进入发送阶段后，即使联络中断，也需要区分发送、实际完成和目标达成。余量充足、目标已修订、回执证据不足或出现矛盾时，本地策略主动交回判断。真实测试也包含“工作已成功，之后可选复查失败”的对照。[本地策略](../src/LittleLoop.Core/LocalBotCognition.cs) · [配对评测](../tests/LittleLoop.Checks/LocalCognitionEvaluation.cs)

最终配对试次对 `deepseek-flash` 运行 10 个合成样例。同一份输入分别交给本地优先和纯模型，按预先设置的动作和证据规则对照。两组均为 0/10 错误，分别请求 6 次和 10 次。4 个本地样例均正确且零请求，其中 2 个覆盖新增规则。其余 6 个样例由模型判断。可比较的 10 对动作、目标及 Harness 一致，完整输出存在措辞差异。早期 9 样例试次中，纯模型曾依据过期未提交回执尝试两次无效委派，宿主校验将其拒绝。详细结果在本机 `data/local-cognition-live-deepseek-followup.json` 和 `data/local-cognition-live-deepseek.json`。

## 验收方法

- **真实长任务**使用隔离 SQLite、新建账号与只读合成项目。验证器经 HTTP 发送自然语言消息并读取持久事件。目标建立后由 Bot 依据回执发出下一轮指令。缺失文件用真实 ACP 工具产生失败。验证器在第二批真实委派运行中发一条补充，并在定时等待时重启服务。它独立知道夹具文件中的随机值，会核对每批回执和最终通知。
- **故障与边界**使用可控时钟和可控执行器，经过真实 SQLite 和后台服务来复现暂停与到期竞争，以及取消、完成后的过期定时标记。原生协议夹具检查日志和不可确定的提交边界。夹具结果与真实 Harness 记录分开。
- **本地认知对照**为相同的结构化输入分别运行本地优先策略和模型策略。每条记录包含输入证据、动作、来源、请求次数和独立验收条件。规则无法确定时交给模型。样例覆盖适用、拒绝接管、边界与反例。
- **自主性指标**按已提交的 Bot 决策、Harness 派发和工具事件分别计数。没有新用户消息的回执、工具结果、定时触发后的决策单列。目标成功率以独立产物与最终通知为准。重复率检查同派发重复结算及已验证步骤被冗余执行，另记录失败、被打断与明确换源。恢复率以重启后原生会话标识和进度证据计算。记忆探针采用已教和未教事项，分开验证保持与误召。
- **模型计量**记录已提交决策中的请求尝试、结果和服务回报 token。格式重试单独计入，缺少用量字段保持未知。崩溃前未提交、旧快照被竞争作废、独立记忆选择器及 Harness 内部推理不在该计量之内。美元金额按可核对的公开费率估算，实际账单需另行核对。[DeepSeek 官方费率](https://api-docs.deepseek.com/quick_start/pricing/)

## 开发试次发现的问题

- `6d9aeda6` 实际触发首选文件工具失败。Bot 另发一次 DeepSeek 派发读取备份，并接力给 Codex。随后 Windows 拒绝测试驱动在原生日志被替换时读入文件，试次提前退出。驱动现会重试该暂态读冲突。
- `bde04e03` 实际完成 21 次目标决策、18 次原生派发、16 个独立检查步骤和最终通知。B02 接到用户补充后原生回合被中断，成功工具结果仍在原派发内。旧验证器只认完整回执，未将该工具证据计入。按修正版重算，该目标完成、复用两个会话、记忆探针 2/2。真实运行另有一次错误派发，Bot 的说明说用 DeepSeek，结构化动作选了 Codex。Codex 报告角色冲突后 Bot 改派 DeepSeek。
- `57546343` 到 B04 后转入人工等待，是一次真实目标失败。两份认知草稿违反同目标下一动作契约，宿主拒绝提交。另有两轮重复核对已正确的末四位，派发 ID 各不相同。B01 中 Harness 自行换源，不能计作 Bot 重规划。宿主现在只对已绑定目标的事件补齐模型省略的目标 ID，仍拒绝显式错误目标和不合法动作。现有日志能确认草稿被拒，无法还原两份被拒草稿的完整内容。
- `ba632f53` 的 B01 工具失败和单独换源已通过，但后续两份委派草稿都没匹配配置中的 Harness ID，Bot 转入人工等待。校验保留了执行器边界。该试次也出现一次重复复核，目标未完成。
- `25d0287c` 同样停在 Harness ID 校验。观察器当时把指令中提到的 B02 误当作当前批次，补充实际在 B01 备份读取时发出。驱动现在需看到 B01 的 Codex 回执及实际读取 B02.txt 的派发才发补充。
- `cb14588f` 使用最终程序集和修正的观察器。B01 的真实工具失败与另轮换源通过。B02 补充在实际派发结束前约 1.95 秒入库，并产生同目标修订。走完 8/16 个阶段，在 B04 后两次草稿被拒，最后触发了定时等待参数校验并进入人工等待。该试次有 12 次目标决策、9 次回执触发的自主推进、10 次原生派发、1 次重复复核和 0 次错误完成。15 次已记账认知 API 调用共 77,132 token，按当日谷价约 0.00994 美元。

## 实测结果

五次有目标结果的试次中，一次从开始走到最终通知，四次因认知动作校验进入人工等待。另有一次因观察器读日志冲突提前终止。试次间的修订包含观察器、输入和适配器变更。最终程序集的试次没有完整通过场景，目标这一路径已得到一次实际执行证据。

| 指标 | 已完成试次 `bde04e03` |
| --- | --- |
| 目标完成 | 1/1，16/16 个独立阶段证据吻合。目标创建后用户补充 1 次，无需用户指挥后续各步。最终通知出现 1 次，包含正确末四位及补充的验收流水号。 |
| Bot 决策 | 21 次目标决策，整个场景 24 次。18 次由 Harness 回执或定时唤醒触发。每次计数对应宿主落库的 Bot 动作。 |
| Harness 调用与重复 | 18 次原生派发。重复结算 0，重复有效阶段 0，另有 1 次无产出错误派发。文件读失败后的显式换源是两次不同的必要派发。 |

核心回归、SQLite 完整回归 296 项、定时及决策专项 87 项和原生协议夹具 14 项通过，计数有重叠。真实模型在两个有正确证据的阶段仍会重复委派，也会产生连续无效动作而停在人工等待。本轮没有验证 MySQL、生产环境长稳运行或开放领域的无人值守成功率。

## 复现入口

```powershell
dotnet run --project tests/LittleLoop.Checks
dotnet run --project tests/LittleLoop.ChatChecks -- --decision-loop
dotnet run --project tests/LittleLoop.ChatChecks -- --harness
dotnet run --project tests/LittleLoop.Checks -- --bot-cognition-evaluate data/local-cognition.json examples/models/deepseek.json
dotnet build src/LittleLoop.Chat
python tests/ChatContinuousLive/direct_http_e2e.py --decision-loop endurance
```

配对命令省略模型配置路径时使用可控模型。真实长任务使用现有的 DeepSeek 只读启动器与 Codex 配置，工作区由驱动替换为合成目录。配置项见[原生验收入口](57-bot-decision-loop.md)。每次运行将完整事件轨迹、指标和成功或失败结果保存到本机 `data/direct-http/<试次>`。
