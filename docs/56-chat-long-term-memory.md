# S3 · 私聊长期记忆

## 设计

首版聚焦两类用户可以核对的记忆。偏好由用户明确写入，首个偏好是完成通知是否附带原任务目标。经历来自既有任务账本，用户可以回顾本私聊最近三项通过宿主验收的目标。回顾只展示目标和任务消息序号，便于追溯原任务卡。

偏好以会话和账号为联合主键，记录最近更改所对应的消息序号。记忆命令与消息消费标记、回复共用事务。完成通知在结果事务中读取当时生效的偏好，成文后进入既有发件箱。更正适用于之后生成的通知，历史通知和聊天消息按原规则保留。普通消息、任务描述和模型回执都不自动写入偏好。

记忆命令仅在启用 LittleLoop 的私聊中由任务操作员使用。群聊和其他私聊各自隔离。偏好只影响通知呈现，不进入执行提示，也不改变目标、工具权限、审批或验收判据。历史经历按需读取，不自动转为经验策略。

## 使用

- `记住偏好：完成通知含目标` 或 `记住偏好：完成通知简洁`
- `查看偏好`
- `忘记偏好`
- `回顾经验`

无偏好时发送简洁通知。忘记偏好会删除持久设置，原来的聊天消息仍可在会话历史中看到。

## 后续评测

首版对照比较同一类任务在有偏好和无偏好时的通知内容，检查重开连接后是否继续生效，以及更正、忘记和会话隔离。

本地构建无警告。`dotnet run --no-build --project tests/LittleLoop.ChatChecks` 在 SQLite 上通过 142 项聊天目标检查。新增场景使用受控回执，验证重开数据库、重复提交、纠正、遗忘以及不读取其他账号或群聊的已完成任务。MySQL 和真实代理的实测留待后续。

后续从验收回执提炼候选经验，记录源任务、成功证据、适用项目和前提。检索必须匹配授权范围及适用条件，用户能查看、纠正、撤回。将已知任务用于提炼、未见过的同类任务用于评测。有记忆与无记忆两组使用同一模型、工具权限和预算，比较独立验收通过率、工具调用次数、成本及需用户纠正的次数。在这组实验提供收益证据前，任务回顾只供人工参考。
