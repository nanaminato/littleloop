# S3 · 私聊长期记忆

## 设计

首版聚焦两类用户可以核对的记忆。偏好由用户明确写入，首个偏好是完成通知是否附带原任务目标。经历来自既有任务账本，用户可以回顾本私聊最近三项通过宿主验收的目标。回顾只展示目标和任务消息序号，便于追溯原任务卡。

偏好以会话和账号为联合主键，记录最近更改所对应的消息序号。记忆命令与消息消费标记、回复共用事务。完成通知在结果事务中读取当时生效的偏好，成文后进入既有发件箱。更正适用于之后生成的通知，历史通知和聊天消息按原规则保留。普通消息、任务描述和模型回执都不自动写入偏好。

记忆命令仅在启用 LittleLoop 的私聊中由任务操作员使用。群聊和其他私聊各自隔离。偏好只影响通知呈现。历史任务回顾与下面的经验提炼分别使用任务账本与宿主验收回执。

## 使用

- `记住偏好：完成通知含目标` 或 `记住偏好：完成通知简洁`
- `查看偏好`
- `忘记偏好`
- `回顾经验`

无偏好时发送简洁通知。忘记偏好会删除持久设置，原来的聊天消息仍可在会话历史中看到。

## 自动提炼与复用

在私聊发送 `启用经验` 后，默认 Codex 执行器完成并通过宿主验收的目标会自动提炼最多三个成功补丁的相对文件路径。记录源任务及版本、项目授权摘要、目标及要求的摘要。旧记录、取消或过期版本、缺少补丁回执的结果不生成经验。

同账号、同私聊、同项目授权、同目标及要求的新任务在首次派发时可得到最近一条匹配经验。经验建议先读这些文件，用当前内容重新判断；提示只携带路径和来源，补丁、命令、模型报告、旧哈希和旧审批不随经验传递。附带引用或上下文锚点的任务及已有执行会话的恢复沿用原流程。源消息被删除后停止检索该经验。

`查看经验` 可列出本私聊最近的经验来源。回复源任务卡发送 `撤回经验` 会删除该项，必要时可撤回较旧的同类记录。`停用经验` 会暂停本私聊之后的提炼和复用。已经提交给执行器的提示保留原执行记录。

## 后续评测

首版对照比较同一类任务在有偏好和无偏好时的通知内容，检查重开连接后是否继续生效，以及更正、忘记和会话隔离。

本地构建无警告。`dotnet run --no-build --project tests/LittleLoop.ChatChecks` 在 SQLite 上通过 142 项聊天目标检查。新增场景使用受控回执，验证重开数据库、重复提交、纠正、遗忘以及不读取其他账号或群聊的已完成任务。MySQL 和真实代理的实测留待后续。

经验闭环增量将同一测试套件扩展至 150 项。新增对照覆盖关闭经验与启用后的提示差异、成功补丁路径投影、重启、授权变化、补充要求、跨私聊隔离和撤回。测试使用受控回执和实际提示构造。

后续可在有记忆与无记忆两组使用同一模型、工具权限和预算，比较独立验收通过率、工具调用次数、成本及需用户纠正的次数。当前的严格匹配只验证闭环，泛化到未见过的同类目标需要独立评测。
