# 调试、开发准则与实验路线

## 开发准则

- C# / .NET，CPU 优先；核心逻辑不依赖 UI、云端或特定模型。
- 先接口、测试与观测，再增加复杂实现；不要为概念文档创建大量空类。
- 单认知事件循环管理可变状态，后台任务通过消息返回；禁止无保护的共享可变状态。
- 输入、决策、检索、行动、反馈可追踪；支持确定性重放与快照。
- 所有概率、置信度、阈值、预算可配置；默认值必须由实验验证。
- 模块版本化、能力声明、沙箱与权限控制；错误隔离、超时、取消。
- 每个实验含基线、成功条件、失败条件、性能与内存测量。
- 区分事实、假设、研究目标和已实现功能；不夸大智能水平。
- 优先单机、离线、可移植；联网能力后置并明确授权。

## 迭代 0：最小认知闭环

实现可重放事件循环、简单概念/关联图、短期记忆、任务目标、规则推理、动作模拟、反馈更新与 CLI 观察工具。验收：同一输入能重放；新反馈改变后续选择；每个选择可解释其来源。

## 迭代 1：记忆实验

注意力写入、多入口检索、时间衰减、模糊回忆、后台巩固、错误纠正。与关键词检索和简单缓存比较。

## 迭代 2：对象连续性与感觉

用合成场景和预录制帧测试同物体关联；随后引入实时视觉流、基础音频语言识别及多模态事件。

## 迭代 3：语言、知识与类比

建立结构化语义中间表示，研究汉语逻辑表达、多语言映射、规则迁移、类比与不确定性处理。

## 迭代 4：动作、元学习和模块生命周期

动作技能、学习自评估、工具接口、受限探索、模块反馈/淘汰、声明式模块生成与隔离测试。

## 首批实验建议

1. 快速浏览材料后，延迟提示能否回忆（与未浏览对照）。
2. 关联图能否通过间接线索找回对象（记录误召回）。
3. 同一物体短暂遮挡后能否保持 ID。
4. 错误规则经反例能否被修正。
5. 学会一个动作后，条件变化时能否迁移或主动停止。
6. 后台巩固是否影响前台事件处理和状态一致性。

## 决策记录

每个重大架构选择写入 ADR，包含背景、候选方案、取舍、风险和实验结果。避免先决定“像人”再反向解释结果。
